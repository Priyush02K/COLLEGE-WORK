## 3. Introduction

**MQTT (Message Queuing Telemetry Transport)** is a lightweight messaging protocol widely used in IoT applications.

MQTT uses a **publish-subscribe communication model**. Devices do not communicate directly with each other. Instead, an MQTT **Broker** receives messages from publishers and forwards them to subscribers.

The basic communication model is:

```text
Publisher → MQTT Broker → Subscriber
```

In this experiment:

```text
Raspberry Pi
    │
    │ Publish
    ▼
┌──────────────────┐
│   HiveMQ Cloud   │
│   MQTT Broker    │
└────────┬─────────┘
         │
         │ Subscribe
         ▼
      Laptop
```

The Raspberry Pi acts as an **MQTT Publisher**, while the laptop or another MQTT client acts as an **MQTT Subscriber**.

# 5. Important MQTT Concepts

| Term           | Description                            | Example              |
| -------------- | -------------------------------------- | -------------------- |
| **MQTT**       | Lightweight messaging protocol for IoT | MQTT                 |
| **Broker**     | Server that manages MQTT messages      | HiveMQ Cloud         |
| **Publisher**  | Client that sends messages             | Raspberry Pi         |
| **Subscriber** | Client that receives messages          | Laptop               |
| **Topic**      | Named communication channel            | `iot/rpi/sensor`     |
| **Message**    | Data sent through a topic              | Temperature = 28.5°C |
| **Client**     | Device/application connected to broker | Raspberry Pi         |
| **QoS**        | Quality of Service level               | 0, 1, 2              |
| **TLS**        | Provides encrypted communication       | MQTT over TLS        |

# 6. Real-Life Analogy

MQTT can be understood using a **post office** analogy.

| MQTT       | Post Office Example         |
| ---------- | --------------------------- |
| Publisher  | Person sending a letter     |
| Message    | Letter                      |
| Topic      | Address/category            |
| Broker     | Post office                 |
| Subscriber | Person receiving the letter |

The publisher sends a message to a topic. The broker receives the message and delivers it to clients subscribed to that topic.

# 13. Part E — Create MQTT Publisher

The Raspberry Pi will act as the **Publisher**.

Create a Python file:

```bash
nano publisher.py
```

Enter the following program:

```python
import json
import time
import random
import ssl
import paho.mqtt.client as mqtt

# HiveMQ Cloud configuration
MQTT_BROKER = "YOUR_HIVEMQ_HOST"
MQTT_PORT = 8883
MQTT_USERNAME = "YOUR_USERNAME"
MQTT_PASSWORD = "YOUR_PASSWORD"

# MQTT topic
MQTT_TOPIC = "iot/rpi/sensor"

# Create MQTT client
client = mqtt.Client(
    mqtt.CallbackAPIVersion.VERSION2,
    client_id="raspberry-pi-publisher"
)

# Set username and password
client.username_pw_set(
    MQTT_USERNAME,
    MQTT_PASSWORD
)

# Enable TLS
client.tls_set(
    cert_reqs=ssl.CERT_REQUIRED
)

# Connect to HiveMQ Cloud
print("Connecting to HiveMQ Cloud...")

client.connect(
    MQTT_BROKER,
    MQTT_PORT,
    60
)

print("Connected successfully!")

# Start MQTT network loop
client.loop_start()

try:
    while True:

        # Simulated sensor values
        temperature = round(random.uniform(25, 35), 2)
        humidity = round(random.uniform(40, 70), 2)

        # Create message
        data = {
            "temperature": temperature,
            "humidity": humidity
        }

        # Convert data into JSON
        message = json.dumps(data)

        # Publish message
        result = client.publish(
            MQTT_TOPIC,
            message
        )

        if result.rc == mqtt.MQTT_ERR_SUCCESS:
            print(
                f"Published: {message}"
            )
        else:
            print("Message publishing failed")

        time.sleep(5)

except KeyboardInterrupt:
    print("\nStopping publisher...")

finally:
    client.loop_stop()
    client.disconnect()
    print("Disconnected from HiveMQ Cloud")
```

# 16. Part F — Create MQTT Subscriber

The subscriber receives messages published to the MQTT topic.

Create:

```bash
nano subscriber.py
```

Use:

```python
import ssl
import paho.mqtt.client as mqtt

# HiveMQ Cloud configuration
MQTT_BROKER = "YOUR_HIVEMQ_HOST"
MQTT_PORT = 8883
MQTT_USERNAME = "YOUR_USERNAME"
MQTT_PASSWORD = "YOUR_PASSWORD"

# MQTT topic
MQTT_TOPIC = "iot/rpi/sensor"


def on_connect(client, userdata, flags, reason_code, properties):
    if reason_code == 0:
        print("Connected to HiveMQ Cloud")
        client.subscribe(MQTT_TOPIC)
        print(f"Subscribed to: {MQTT_TOPIC}")
    else:
        print("Connection failed")


def on_message(client, userdata, message):
    print("\nMessage received")
    print("Topic:", message.topic)
    print("Data:", message.payload.decode())


client = mqtt.Client(
    mqtt.CallbackAPIVersion.VERSION2,
    client_id="mqtt-subscriber"
)

client.username_pw_set(
    MQTT_USERNAME,
    MQTT_PASSWORD
)

client.tls_set(
    cert_reqs=ssl.CERT_REQUIRED
)

client.on_connect = on_connect
client.on_message = on_message

print("Connecting to HiveMQ Cloud...")

client.connect(
    MQTT_BROKER,
    MQTT_PORT,
    60
)

client.loop_forever()
```

# 22. Understanding the Experiment

The important point is that the Raspberry Pi and laptop do **not** need to communicate directly.

Instead:

```text
Raspberry Pi
     │
     │ Publish
     ▼
HiveMQ Cloud
     │
     │ Forward
     ▼
Subscriber
```

The broker acts as the central communication point.

This makes MQTT useful for IoT systems where many devices need to exchange data.

# 23. Edge Computing Connection

The Raspberry Pi can be considered an **Edge Device** because it is located close to the physical sensors.

For example:

```text
             CLOUD
               │
        HiveMQ Cloud
               │
               │
             Internet
               │
               ▼
        ┌──────────────┐
        │ Raspberry Pi │
        │ EDGE DEVICE  │
        └──────┬───────┘
               │
          ┌────┴────┐
          ▼         ▼
       DHT11      Camera
       Sensor     Sensor
```

The Raspberry Pi can:

* Collect sensor data.
* Filter data.
* Process data locally.
* Detect abnormal values.
* Send selected information to the Cloud.

Therefore, MQTT can act as a communication mechanism between **Edge devices and Cloud services**.

# 24. Advantages of MQTT

1. Lightweight protocol.
2. Suitable for resource-constrained IoT devices.
3. Requires low bandwidth.
4. Supports publish-subscribe communication.
5. Supports Quality of Service.
6. Supports secure communication using TLS.
7. Suitable for large numbers of IoT devices.
8. Decouples publishers and subscribers.

---

# 25. MQTT QoS Levels

MQTT provides three Quality of Service levels.

|   QoS | Name          | Description                                                 |
| ----: | ------------- | ----------------------------------------------------------- |
| **0** | At most once  | Message is delivered without confirmation                   |
| **1** | At least once | Message is delivered at least once; duplicates are possible |
| **2** | Exactly once  | Message is delivered exactly once                           |

For simple sensor monitoring, QoS 0 is often sufficient. Applications requiring stronger delivery guarantees may use QoS 1 or QoS 2.
