# Experiment 07 — Develop a Simple Containerized Application Using Docker

## Objective

To develop a simple Flask web application and containerize it using Docker. The application will be packaged into a Docker image and executed inside a Docker container.

---

## Learning Outcomes

After completing this experiment, students will be able to:

- Create a simple Flask web application.
- Create a `requirements.txt` file.
- Write a Dockerfile.
- Build a Docker image.
- Run an application inside a Docker container.
- Map a host port to a container port.
- Manage Docker containers using basic commands.

---

## Software Requirements

- Windows 10/11
- Docker Desktop
- Python 3.x
- Web Browser
- Command Prompt / PowerShell
- Text Editor / Notepad

> **Prerequisite:** Docker Desktop should be installed and running. Docker installation and basic Docker commands were covered in the previous experiment.

# Part A — Create the Flask Application

## Step 1: Create the Project Folder

Open **Command Prompt**.

Go to Desktop:

```cmd
cd Desktop
```

Create a project folder:

```cmd
mkdir docker-flask-app
```

Enter the folder:

```cmd
cd docker-flask-app
```

Check the current location:

```cmd
cd
```

Expected:

```text
C:\Users\STUDENT\Desktop\docker-flask-app
```

---

## Step 2: Create `app.py`

Run:

```cmd
notepad app.py
```

Paste the following code:

```python
from flask import Flask

app = Flask(__name__)

@app.route("/")
def home():
    return "<h1>Hello from Docker!</h1><p>My first containerized Flask application is running.</p>"

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)
```

Save and close the file.

---

## Step 3: Create `requirements.txt`

Run:

```cmd
notepad requirements.txt
```

Add:

```text
Flask
```

Save and close the file.

The project structure should now be:

```text
docker-flask-app
│
├── app.py
└── requirements.txt
```

# Part C — Create the Dockerfile

## Step 6: Create `Dockerfile`

Run:

```cmd
notepad Dockerfile
```

> **Important:** The filename must be exactly `Dockerfile`, without `.txt`.

Add the following:

```dockerfile
FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt .

RUN pip install --no-cache-dir -r requirements.txt

COPY app.py .

EXPOSE 5000

CMD ["python", "app.py"]
```

Save and close the file.

---

## Understanding the Dockerfile

| Dockerfile Instruction | Purpose |
|---|---|
| `FROM` | Selects the base image |
| `WORKDIR` | Sets the working directory inside the container |
| `COPY` | Copies files from the project into the image |
| `RUN` | Executes a command while building the image |
| `EXPOSE` | Specifies the application port |
| `CMD` | Specifies the command to run when the container starts |

### Explanation

```dockerfile
FROM python:3.12-slim
```

Uses a lightweight Python image as the base image.

```dockerfile
WORKDIR /app
```

Sets `/app` as the working directory inside the container.

```dockerfile
COPY requirements.txt .
```

Copies `requirements.txt` into the container.

```dockerfile
RUN pip install --no-cache-dir -r requirements.txt
```

Installs Flask inside the Docker image.

```dockerfile
COPY app.py .
```

Copies the Flask application into the container.

```dockerfile
EXPOSE 5000
```

Indicates that the application uses port `5000`.

```dockerfile
CMD ["python", "app.py"]
```

Starts the Flask application when the container runs.

## Step 7: Check Docker

Run:

```cmd
docker --version
```

Then:

```cmd

```

Make sure Docker Desktop is running.

---

## Step 8: Verify Project Files

Run:

```cmd

```

```text
Dockerfile
app.py
```

---

## Step 9: Build the Docker Image

Run:

```cmd
docker build -t flask-docker-app .
```

### Command Explanation

| Part | Meaning |
|---|---|
| `docker build` | Builds a Docker image |
| `-t` | Assigns a name/tag to the image |
| `flask-docker-app` | Name of the Docker image |
| `.` | Uses the current directory as the build context |

---

## Step 10: Verify the Docker Image

Run:

```cmd
docker images
```

You should see an entry similar to:

```text
REPOSITORY         TAG       IMAGE ID       CREATED
flask-docker-app   latest    xxxxxxxxxxxx   ...
```

The Docker image has now been created.

---

# Part E — Run the Docker Container

## Step 11: Start the Container

Run:

```cmd
docker run -d -p 5000:5000 --name flask-container flask-docker-app
```

### Command Explanation

| Option | Purpose |
|---|---|
| `docker run` | Creates and starts a container |
| `-d` | Runs the container in detached/background mode |
| `-p 5000:5000` | Maps host port 5000 to container port 5000 |
| `--name flask-container` | Assigns a name to the container |
| `flask-docker-app` | Specifies the Docker image to use |

### Port Mapping

```text
Host Computer              Docker Container
     5000   ───────────────►   5000
```

---

## Step 12: Check the Running Container

Run:

```cmd
docker ps
```

You should see something similar to:

```text
CONTAINER ID   IMAGE              PORTS
xxxxxxxxxxxx   flask-docker-app   0.0.0.0:5000->5000/tcp
```

This confirms that the container is running.

# Viva Questions

### 1. What is Docker?

Docker is a platform used to package and run applications in lightweight, isolated containers.

### 2. What is a Docker image?

A Docker image is a read-only package containing the application, dependencies, libraries, and instructions required to create a container.

### 3. What is a Docker container?

A container is a running instance of a Docker image.

### 4. What is a Dockerfile?

A Dockerfile is a text file containing instructions used to build a Docker image.

### 5. What does `docker build` do?

It creates a Docker image from a Dockerfile.

### 6. What does `docker run` do?

It creates and starts a container from a Docker image.

### 7. What does `-p 5000:5000` mean?

It maps port `5000` of the host computer to port `5000` inside the Docker container.

### 8. Why is `host="0.0.0.0"` used in Flask?

It allows the Flask application to accept connections from outside the container.

### 9. What is the difference between an image and a container?

An **image** is the packaged application template, while a **container** is the running instance of that image.

### 10. What is the advantage of containerization?

Containerization provides portability, isolation, consistency, and easier deployment of applications.
