**Experiment 07 — Develop a Simple Containerized Application Using Docker**

**Objective**

To containerize the Flask-based Event Registration Application developed in Experiment 01 using Docker, build a Docker image, run the application inside a Docker container, and access it through a web browser.

Existing Application

We already have:

    event-registration/
    │
    ├── app.py
    └── templates/
        └── index.html

For Experiment 07, we will add:

    event-registration/
    │
    ├── app.py
    ├── requirements.txt
    ├── Dockerfile
    └── templates/
        └── index.html


**Step 1 — Open the Experiment 01 Project**

Open Command Prompt and go to your project folder.

For example:

    cd Desktop
    cd event-registration

Check the files:

    dir

You should have:

    app.py
    templates

**Step 2 — Modify app.py**

Because the application will run inside a Docker container, change the last part of app.py.

Use this version:

```python
from flask import Flask, render_template, request

app = Flask(__name__)

@app.route("/", methods=["GET", "POST"])
def register():

    if request.method == "POST":
        name = request.form["name"]
        email = request.form["email"]
        phone = request.form["phone"]
        event = request.form["event"]

        return f"""
        <h1>Registration Successful!</h1>
        <p><strong>Name:</strong> {name}</p>
        <p><strong>Email:</strong> {email}</p>
        <p><strong>Phone:</strong> {phone}</p>
        <p><strong>Event:</strong> {event}</p>
        """

    return render_template("index.html")


if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)
```

Important change

Previously we had:

**app.run(debug=True)**

Now we use:

**app.run(host="0.0.0.0", port=5000)**

This allows Flask to receive connections from outside the Docker container.

**Step 3 — Create requirements.txt**

Run:

**notepad requirements.txt**

Enter:

    Flask

Save and close.

**Step 4 — Create the Dockerfile**

Run:

**notepad Dockerfile**

Enter:

```python
FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt .

RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 5000

CMD ["python", "app.py"]
```

Save and close.

**Step 5 — Understand the Dockerfile**

| Instruction               | Purpose                                    |
| ------------------------- | ------------------------------------------ |
| `FROM python:3.12-slim`   | Provides Python environment                |
| `WORKDIR /app`            | Creates working directory inside container |
| `COPY requirements.txt .` | Copies dependency file                     |
| `RUN pip install...`      | Installs Flask                             |
| `COPY . .`                | Copies application files and templates     |
| `EXPOSE 5000`             | Indicates Flask port                       |
| `CMD`                     | Starts the Flask application               |


The important difference from our previous simple Docker example is:

    COPY . .

This copies both app.py and the templates folder into the container.

    docker build

Build a Docker image.

    -t event-registration-app

    event-registration-app

**Step 9 — Verify the Image**

Run:

    docker images

You should see:

    REPOSITORY                TAG       IMAGE ID
    event-registration-app    latest    xxxxxxxxx

Your Flask application is now packaged as a Docker image.

**Step 10 — Run the Docker Container**

Run:

    docker run -d -p 5000:5000 --name event-registration-container event-registration-app

Meaning of the command
-d

Runs the container in the background.

-p 5000:5000

Maps:

Host Port 5000 → Container Port 5000
--name event-registration-container

Gives the container a name.

event-registration-app

Specifies the image from which the container is created.

**Step 11 — Check the Running Container**

Run:

    docker ps

You should see something similar to:

    CONTAINER ID   IMAGE                    PORTS
    xxxxxxxxxxxx   event-registration-app   0.0.0.0:5000->5000/tcp

This confirms that the Event Registration application is running inside Docker.

# Viva Questions

### 1. What is Docker?

Docker is a platform used to package and run applications in lightweight, isolated containers.

### 2. What is a Docker image?

A Docker image is a read-only package containing the application, dependencies, libraries, and instructions required to create a container.

### 3. What is a Docker container?

A container is a running instance of a Docker image.

### 4. What is a Dockerfile?

A Dockerfile is a text file containing instructions used to build a Docker image.

### 5. What does `docker build` do?

It creates a Docker image from a Dockerfile.

### 6. What does `docker run` do?

It creates and starts a container from a Docker image.

### 7. What does `-p 5000:5000` mean?

It maps port `5000` of the host computer to port `5000` inside the Docker container.

### 8. Why is `host="0.0.0.0"` used in Flask?

It allows the Flask application to accept connections from outside the container.

### 9. What is the difference between an image and a container?

An **image** is the packaged application template, while a **container** is the running instance of that image.

### 10. What is the advantage of containerization?

Containerization provides portability, isolation, consistency, and easier deployment of applications.
