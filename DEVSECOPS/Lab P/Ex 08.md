**Experiment 08 — Continuous Deployment Using Ansible**

What we will finally achieve

```js
Flask Application
       ↓
Dockerfile
       ↓
Docker Image
       ↓
Ansible
       ↓
Target Ubuntu Machine
       ↓
Docker Container
       ↓
Application Running
```

**Step 1 — Understand the Setup**

We need 2 Ubuntu machines.

**Machine 1 — Ansible Control Machine**
This is where we install and run Ansible.

```js
Ubuntu
   +
Ansible
```

**Machine 2 — Target Machine**

This is where our application will be deployed.

```js
Ubuntu
   +
Docker
   +
Flask Application
```


Think of it like:

```js
CONTROL MACHINE                  TARGET MACHINE

   Ansible  ───── SSH ───────→    Ubuntu
                                  Docker
                                  Flask App
```


**For the lab**

You can use:

- VM 1: Ubuntu → Control Machine
- VM 2: Ubuntu → Target Machine

If you are using VirtualBox, create two Ubuntu VMs.

**Step 2 — Check Ubuntu**

On both machines, open Terminal and run:
```js
lsb_release -a
```


You should get information about your Ubuntu version.
```js
Ubuntu 24.04
```
You can continue if both machines are working.


**Step 3 — Find the IP Address of the Target Machine**

Go to the Target Machine.

Run:

```js
ip addr
```


Look for something like:

```js
inet 192.168.1.20
```

For example:

```js
Target Machine IP = 192.168.1.20
```

⚠️ Your IP will probably be different.

Write down your actual IP address.


**Step 4 — Test Network Connection**

Now go to the Control Machine.

Run:

```js
ping 192.168.1.20
```

Replace 192.168.1.20 with your target machine's IP.

```js
64 bytes from 192.168.1.20
64 bytes from 192.168.1.20
64 bytes from 192.168.1.20
```


Press:

```js
Ctrl + C
```

to stop.

If ping works

Good ✅

**Step 5 — Install SSH on Target Machine**


Now work on the Target Machine.

First update Ubuntu

```js
sudo apt update
```

Then install SSH server:

```js
sudo apt install openssh-server -y
```


Check SSH:

```js
sudo systemctl status ssh
```


You should see:

```js
Active: active (running)
```

If it is not running, execute:

```js
sudo systemctl start ssh
```


Then:

```js
sudo systemctl enable ssh
```

**Step 6 — Find Target Username**

On the Target Machine, run:

```js
whoami
```

For example, it may show:

```js
student
```

So we now have:

```js
Target IP       = 192.168.1.20
Target Username = student
```
Your values may be different.

**Step 7 — Test SSH from Control Machine**

Now go back to the Control Machine.

```js
ssh student@192.168.1.20
```

**Replace**:

- student with your target username
- 192.168.1.20 with your target IP

The first time, you may get:

Are you sure you want to continue connecting?

Type:

```js
yes
```

Then enter the Target Machine password.

If successful, your terminal will change to something like:

```js
student@ubuntu:~$
```

🎉 This means the Control Machine can remotely access the Target Machine.

Exit the SSH connection:

```js
exit
```

You should return to the Control Machine.

**Step 8 — Install Ansible**


Run:

```js
sudo apt update

```

Then:

```js
sudo apt install ansible -y

```

Check:

```js
ansible --version

```

You should see something similar to:

```js
ansible [core ...]

```

✅ Ansible is installed.







**Step 9 — Configure SSH Key Authentication**

We already tested SSH using a password. Now we will configure SSH Key Authentication so Ansible can connect to the Target Machine automatically.

Why do we need this?

Without SSH key:

```js
Ansible → SSH → Password required ❌

```

With SSH key:

```js
Ansible → SSH Key → Target Machine → Connected ✅

```

**9.1 Check whether an SSH key already exists**

On the Control Machine, run:

```js
ls ~/.ssh

```

You may see:

```js
id_rsa
id_rsa.pub

```

or:

```js
id_ed25519
id_ed25519.pub

```

- If you already have a key, you can use it.
- If you don't see these files, create a new key.
- 

**9.2 Generate SSH Key**

On the Control Machine, run:

```js
ssh-keygen

```

You will see something like:

```js
Generating public/private rsa key pair.
Enter file in which to save the key:
```


Just press Enter.

Then:

```js
Enter passphrase:

```


For this lab, press Enter.

Again:

```js
Enter same passphrase again:

```

Press Enter.

You should see:

```js
Your identification has been saved in /home/student/.ssh/id_rsa
Your public key has been saved in /home/student/.ssh/id_rsa.pub
```



**9.3 Copy the Public Key to Target Machine**

Now run this on the Control Machine:

```js
ssh-copy-id student@192.168.1.20

```

Replace:

```js
student
```


with your Target Machine username.

Replace:

```js
192.168.1.20

```

with your Target Machine IP.

Example:

```js
ssh-copy-id student@192.168.1.20

```

It will ask for the Target Machine password one last time.

Enter it.

You should see something similar to:

Number of key(s) added: 1

```js
9.4 Test SSH Without Password

```

Now run:

```js
ssh student@192.168.1.20

```

If everything is configured correctly, you should enter the Target Machine without being asked for its password.

You will see:

```js
student@ubuntu:~$

```

🎉 SSH key authentication is working.

Exit:

exit

**9.5 Why did we do this?**

The process is:

```js
CONTROL MACHINE
      │
      │ SSH Key
      ↓
TARGET MACHINE
      │
      ↓
Authentication
      │
      ↓
Connected ✅

```

The important files are:

| File         | Meaning                              |
| ------------ | ------------------------------------ |
| `id_rsa`     | Private key — **keep it safe**       |
| `id_rsa.pub` | Public key — copied to target server |


Step 9 Complete ✅
