# Experiment No. 05

# Demonstrate Continuous Integration and Continuous Delivery Using Jenkins

## Aim

To demonstrate Continuous Integration (CI) and Continuous Delivery (CD) using Jenkins by automatically retrieving source code from GitHub, building the application, running tests, and executing a deployment stage.

## Learning Objectives

After completing this experiment, students will be able to:

- Understand the CI/CD workflow.
- Connect Jenkins with a GitHub repository.
- Create a Jenkins Pipeline.
- Retrieve source code from GitHub.
- Build and test an application using Jenkins.
- Understand successful and failed builds.
- Understand how DevSecOps extends CI/CD by adding security checks.

## Software Requirements

| Software | Purpose |
|---|---|
| Git | Source Code Management |
| GitHub | Remote Source Code Repository |
| Jenkins | CI/CD Automation Server |
| Python | Application Development |
| Flask | Web Application Framework |
| Pytest | Application Testing |
| Web Browser | Access Jenkins and GitHub |

## Prerequisites

Students should have completed:

- Git and GitHub basics.
- Jenkins installation on Windows or Linux.
- Basic Python programming.
- Basic understanding of source code repositories.

## CI/CD Concept

```text
Developer
    |
    | git push
    v
GitHub Repository
    |
    v
Jenkins
    |
    +----> Checkout Code
    |
    +----> Build
    |
    +----> Test
    |
    +----> Deploy
    |
    v
Application
```

### Continuous Integration

Continuous Integration means frequently integrating code changes into a shared repository and automatically building and testing those changes.

### Continuous Delivery

Continuous Delivery extends CI by automatically preparing a successfully tested application for release or deployment.

### DevSecOps

DevSecOps integrates security checks into the CI/CD pipeline.

```text
CI/CD:
Code → Build → Test → Deploy

DevSecOps:
Code → Build → Test → Security Scan → Deploy
```

```python
    assert b"Welcome to Jenkins CI/CD Demo" in response.data
```

## Step 19: Add Jenkins Pipeline

### Windows Jenkins

```groovy
pipeline {
    agent any

    stages {

        stage('Checkout') {
            steps {
                git branch: 'main',
                    url: 'YOUR_GITHUB_REPOSITORY_URL'
            }
        }

        stage('Build') {
            steps {
                bat 'python -m pip install -r requirements.txt'
            }
        }

        stage('Test') {
            steps {
                bat 'pytest'
            }
        }

        stage('Deploy') {
            steps {
                echo 'Deploying application...'
            }
        }
    }

    post {
        success {
            echo 'CI/CD Pipeline completed successfully!'
        }

        failure {
            echo 'CI/CD Pipeline failed!'
        }
    }
}
```

Replace `YOUR_GITHUB_REPOSITORY_URL` with your GitHub repository URL.

### Linux Jenkins

```groovy
pipeline {
    agent any

    stages {

        stage('Checkout') {
            steps {
                git branch: 'main',
                    url: 'YOUR_GITHUB_REPOSITORY_URL'
            }
        }

        stage('Build') {
            steps {
                sh 'python3 -m pip install -r requirements.txt'
            }
        }

        stage('Test') {
            steps {
                sh 'pytest'
            }
        }

        stage('Deploy') {
            steps {
                echo 'Deploying application...'
            }
        }
    }

    post {
        success {
            echo 'CI/CD Pipeline completed successfully!'
        }

        failure {
            echo 'CI/CD Pipeline failed!'
        }
    }
}
```

# Part M — DevSecOps Extension

Traditional CI/CD:

```text
Code
  ↓
Build
  ↓
Test
  ↓
Deploy
```

DevSecOps:

```text
Code
  ↓
Build
  ↓
Test
  ↓
Security Scan
  ↓
Quality Check
  ↓
Deploy
```

Possible security checks include:

- Dependency vulnerability scanning.
- Static Application Security Testing (SAST).
- Secret detection.
- Container image scanning.
- Software Composition Analysis (SCA).

This demonstrates how security becomes part of the development and delivery process rather than being performed only at the end.
