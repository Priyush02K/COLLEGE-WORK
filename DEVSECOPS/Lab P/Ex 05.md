# Experiment No. 05

# Integrate Jenkins with GitHub for Continuous Integration and Continuous Delivery

## Based on Experiment 01 — Flask User Registration Form

---

## Aim

To integrate Jenkins with a GitHub repository containing the Flask User Registration Form developed in Experiment 01 and demonstrate the basic Continuous Integration and Continuous Delivery (CI/CD) workflow.

---

## Learning Objectives

After completing this experiment, students will be able to:

- Connect a GitHub repository with Jenkins.
- Configure Jenkins to retrieve source code from GitHub.
- Create a Jenkins Pipeline.
- Build a Flask application using Jenkins.
- Execute application tests through Jenkins.
- Understand the CI/CD workflow.
- Understand how GitHub changes can trigger Jenkins builds.
- Understand the role of Jenkins in DevSecOps.

---

# Part F — Configure GitHub Repository Access

There are two common situations.

## Case 1 — Public GitHub Repository

If the Experiment 01 repository is public, Jenkins can usually clone it without GitHub credentials.

Example:

```text
https://github.com/USERNAME/Flask-User-Registration.git
```

For the first laboratory demonstration, a public repository is the simplest setup.

---

## Case 2 — Private GitHub Repository

If the repository is private, Jenkins requires credentials.

Go to:

```text
Manage Jenkins
        |
        v
    Credentials
        |
        v
      System
        |
        v
Global credentials
```

Click:

```text
Add Credentials
```

Use an appropriate GitHub authentication method, such as a GitHub Personal Access Token.

Example:

```text
Kind:        Username with password
Username:    Your GitHub username
Password:    GitHub Personal Access Token
ID:          github-credentials
```

Click:

```text
Create
```

> Never put a GitHub password or token directly inside the Jenkinsfile.

# Part I — Connect Jenkins to GitHub

## Step 10: Add Checkout Stage

For a public repository, use:

```groovy
stage('Checkout') {
    steps {
        git branch: 'main',
            url: 'https://github.com/USERNAME/Flask-User-Registration.git'
    }
}
```

Replace:

```text
USERNAME
```

with the actual GitHub username.

---

## Step 11: Private Repository Checkout

For a private repository:

```groovy
stage('Checkout') {
    steps {
        git branch: 'main',
            credentialsId: 'github-credentials',
            url: 'https://github.com/USERNAME/Flask-User-Registration.git'
    }
}
```

The `credentialsId` must match the credential ID created in Jenkins.

---

# Part J — Create the Complete Jenkins Pipeline

## Step 12: Windows Jenkins Pipeline

If Jenkins is running on Windows:

```groovy
pipeline {
    agent any

    stages {

        stage('Checkout') {
            steps {
                git branch: 'main',
                    url: 'YOUR_GITHUB_REPOSITORY_URL'
            }
        }

        stage('Build') {
            steps {
                bat 'python -m pip install -r requirements.txt'
            }
        }

        stage('Test') {
            steps {
                bat 'pytest'
            }
        }

        stage('Deploy') {
            steps {
                echo 'Deploying Flask User Registration Application...'
            }
        }
    }

    post {
        success {
            echo 'CI/CD Pipeline completed successfully!'
        }

        failure {
            echo 'CI/CD Pipeline failed!'
        }
    }
}
```

Replace:

```text
YOUR_GITHUB_REPOSITORY_URL
```

with the actual GitHub repository URL.

# Part O — Understand the Checkout Stage

The Checkout stage downloads the latest source code from GitHub.

```text
GitHub Repository
       |
       | git clone / checkout
       v
Jenkins Workspace
```

Jenkins stores the checked-out source code in its workspace for the current build.

## Step 33: Enter Jenkins Webhook URL

The commonly used Jenkins GitHub webhook endpoint is:

```text
http://YOUR-JENKINS-SERVER/github-webhook/
```

For example, if Jenkins is available at:

```text
http://192.168.1.10:8080
```

the webhook endpoint is:

```text
http://192.168.1.10:8080/github-webhook/
```

> `localhost` is normally not reachable by GitHub's public webhook service. Jenkins must be reachable from the GitHub service for an external GitHub webhook to work.

---

## Step 34: Configure Webhook

Set:

```text
Payload URL:
http://YOUR-JENKINS-SERVER/github-webhook/
```

Content type:

```text
application/json
```

Select:

```text
Just the push event
```

Save the webhook.

If Jenkins is installed on your personal computer and is available only through:


For a classroom demonstration, first use:

```text
GitHub
```

After that, automatic webhooks can be demonstrated using a Jenkins server that is reachable by GitHub or an appropriately configured lab/network environment.

# Part Z — DevSecOps Extension

The current pipeline is:

```text
Checkout
    ↓
Build
    ↓
Test
    ↓
Deploy
```

For DevSecOps, add security before deployment:

```text
Checkout
    ↓
Build
    ↓
Test
    ↓
Security Scan
    ↓
Quality Check
    ↓
Deploy
```

Possible security activities include:

- Dependency vulnerability scanning.
- Static Application Security Testing (SAST).
- Secret detection.
- Software Composition Analysis (SCA).
- Container image scanning.

The important concept is:

```text
DevOps
Code → Build → Test → Deploy

DevSecOps
Code → Build → Test → Security → Deploy
```
