
# Experiment 07 — Website Technology Identification and Vulnerability Reporting

### Aim

To utilize OSINT and website technology-fingerprinting tools to identify the **CMS, web server, programming technologies, frameworks, libraries, analytics platforms, and other technologies** used by an authorized website and prepare a basic vulnerability report based on publicly available security information.

**Main workflow**

    Authorized Website
            ↓
    Technology Fingerprinting
            ↓
    Identify CMS / Server / Framework / Libraries
            ↓
    Record Versions
            ↓
    Cross-Check Public Vulnerability Databases
            ↓
    Identify Potential Vulnerabilities
            ↓
    Risk Classification
            ↓
    Prepare Vulnerability Report

**Recommended tools**
| Tool                        | Purpose                                                   |
| --------------------------- | --------------------------------------------------------- |
| **Wappalyzer**              | Identify website technologies                             |
| **WhatWeb**                 | Technology fingerprinting                                 |
| **BuiltWith**               | Website technology profiling                              |
| **OWASP ZAP**               | Passive web-security analysis and technology observations |
| **Browser Developer Tools** | Inspect headers, source code and loaded resources         |
| **NVD**                     | Search publicly documented CVEs                           |
| **CVE.org**                 | Search CVE records                                        |
| **WPScan**                  | WordPress-specific assessment — authorized sites only     |


Vulnerability Report Format

A good report can contain:

1. Finding: Name of the vulnerability
2. Affected component: CMS/server/library and version
3. Severity: Low / Medium / High / Critical
4. Evidence: What you observed during the assessment
5. Impact: What could happen if the vulnerability is exploitable
6. Recommendation: How the administrator should remediate it
7. References: CVE/vendor advisory

Expected Result

The technologies used by the authorized website are identified and documented. Potential security issues are correlated with known vulnerabilities, and a structured vulnerability report is produced containing the evidence, severity, impact, and recommended remediation.

For a college practical, the easiest demonstration is:
Wappalyzer/WhatWeb → identify technologies → record versions → check NVD/vendor advisories → prepare vulnerability table.
